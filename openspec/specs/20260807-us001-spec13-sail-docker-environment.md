# Spec 13: Dockerised Environment with Laravel Sail

## Metadata
- **User Story**: [US-001](../features/20260511-user-management-and-application-bootstrap.md)
- **Type**: Backend (Laravel Admin Panel)
- **Branch**: feature/20260807_us001_sail_and_manual_tests
- **Estimated effort**: M
- **Depends on**: Specs 1–12 and the Playwright spec (the whole app must already run on the host)

## Overview

Bring the application up under **Laravel Sail** so the environment is reproducible and no longer depends on the PHP extensions and MySQL instance that happen to be installed on the host. `laravel/sail` v1.58 is already a dev dependency; what is missing is `docker-compose.yml`, the environment wiring, and the migration of the two existing test suites to run against the containers.

The host currently satisfies the app only after manual intervention: `pdo_mysql` had to be installed into PHP 8.4, and MySQL is served by an unrelated Docker container shared with other projects. Sail removes both couplings.

## Architecture Context

- `docker-compose.yml` — generated by `sail:install`, committed to the repository
- `.env` / `.env.testing` — `DB_HOST` becomes `mysql` (the compose service name) instead of `127.0.0.1`
- `phpunit.xml` — currently hardcodes `DB_HOST=127.0.0.1`, unreachable from inside the container
- `playwright.config.ts` and `tests/e2e/user-management.spec.ts` — currently shell out to host `php artisan`
- `README.md` — setup instructions

### Host constraints that shape this spec

| Constraint | Consequence |
|---|---|
| Host port **3306 is already taken** by an unrelated `mysql:8.3` container | Sail's MySQL must publish on a different host port; use `FORWARD_DB_PORT=3307` |
| Playwright's `baseURL` and the README both use port **8000** | Set `APP_PORT=8000` so the URL stays valid |
| The project targets PHP **8.2+** and runs on 8.4 | Use the `8.4` Sail runtime, which exists in `vendor/laravel/sail/runtimes/8.4` |
| Playwright browsers are installed on the **host** | Playwright keeps running on the host against the Sail-served app; only its Artisan calls move into the container |

## Implementation Steps

### Step 0: Verify prerequisites

```bash
docker --version
docker ps                      # confirm the daemon is reachable
./vendor/bin/sail --version    # sail is already installed
```

Confirm host port 8000 is free and note that 3306 is not.

---

### Step 1: Generate the compose file

```bash
php artisan sail:install --with=mysql
```

Choose only **mysql**. Redis, Meilisearch, Mailpit and Selenium are not used by US-001 and would add containers for nothing.

This writes `docker-compose.yml`. Commit it.

---

### Step 2: Pin the PHP runtime to 8.4

In `docker-compose.yml`, confirm the app service builds from the 8.4 runtime:

```yaml
build:
    context: './vendor/laravel/sail/runtimes/8.4'
    dockerfile: Dockerfile
    args:
        WWWGROUP: '${WWWGROUP}'
image: 'sail-8.4/app'
```

---

### Step 3: Wire the environment

Add to `.env`:

```dotenv
APP_PORT=8000
FORWARD_DB_PORT=3307
WWWGROUP=1000
WWWUSER=1000
DB_HOST=mysql
```

`DB_HOST=mysql` is the compose service name and only resolves **inside** the network. Apply the same change to `.env.testing`, keeping `DB_DATABASE=fichaccom_e2e`.

> `WWWUSER`/`WWWGROUP` must match the host user id (`id -u` / `id -g`) or files written by the container will be owned by the wrong user.

---

### Step 4: Point PHPUnit at the container database

`phpunit.xml` currently pins `DB_HOST=127.0.0.1`, which inside the app container resolves to the app container itself. Change it to the service name:

```xml
<env name="DB_HOST" value="mysql"/>
<env name="DB_DATABASE" value="fichaccom_test"/>
```

Keep `DB_CONNECTION=mysql`: the decision to test against the real engine rather than SQLite still stands (see Spec 11).

From this point the supported command is `sail test`, not host `php artisan test`.

---

### Step 5: Create the two extra databases

Sail's MySQL container creates only the database named in `DB_DATABASE`. The suites need two more:

```bash
sail up -d
sail mysql -e "CREATE DATABASE IF NOT EXISTS fichaccom_test  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
sail mysql -e "CREATE DATABASE IF NOT EXISTS fichaccom_e2e   CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

Alternatively add a `docker/mysql/create-testing-database.sh` init script so fresh volumes get them automatically.

---

### Step 6: Bring the stack up and migrate

```bash
sail up -d
sail composer install
sail npm install
sail npm run build
sail artisan migrate --seed
```

Confirm `http://localhost:8000/login` renders.

---

### Step 7: Move the Playwright suite onto the Sail stack

Two changes are required, both in already-closed work — call them out in the PR:

1. `playwright.config.ts` — the app is served by Sail's nginx, so `artisan serve` must not be started. Replace the `webServer` block with a reachability check, or point `command` at `sail up -d` with `reuseExistingServer: true`.
2. `tests/e2e/user-management.spec.ts` — the `beforeEach` shells out to host Artisan. It must run inside the container:

```ts
execSync('./vendor/bin/sail artisan migrate:fresh --seed --seeder=E2ESeeder --env=testing', {
    stdio: 'pipe',
});
```

---

### Step 8: Verify both suites inside the stack

```bash
sail test                 # expect the full unit + feature suite green
npx playwright test       # expect 4 scenarios green
```

---

### Step LAST: Update Documentation

Rewrite the README setup section around Sail: `sail up -d`, `sail artisan …`, `sail test`, `sail npm run build`. State explicitly that host port 3306 is not used and that MySQL is published on 3307. Keep the host-based instructions only if they still work.

## Tests

No new automated tests are added: this spec changes how the existing suites execute, and the verification is that they keep passing unchanged inside the containers.

| # | Check | Expected |
|---|---|---|
| 1 | `sail up -d` | All services report healthy; no port conflict on 3306 |
| 2 | `sail test` | Same test count as on the host, all green |
| 3 | `npx playwright test` | 4 scenarios green against the Sail-served app |
| 4 | `curl -o /dev/null -w '%{http_code}' http://localhost:8000/login` | `200` |
| 5 | Host `mysql` container untouched | The unrelated container is still running and its data intact |
